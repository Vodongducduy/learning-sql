Lộ trình thực hành Automation Testing trong 14 ngày

> **Đối tượng:** Học viên mới, chưa từng viết test automation hoặc mới biết TypeScript ở mức rất cơ bản.

> **Công nghệ:** TypeScript, Playwright Test, Cucumber ở mức nhập môn.

> **Thời lượng:** 14 ngày, khoảng 2 giờ mỗi ngày; ngày mini project có thể cần 3 giờ.

> **Mục tiêu:** Sau khóa học, học viên có thể đọc, chạy, debug, sửa và viết thêm các UI automation test cơ bản trong một dự án có sẵn.

1. Phạm vi khóa học

1.1. Nội dung bắt buộc thực hành

  • TypeScript tối thiểu để đọc và viết test.
  • Tạo và chạy project Playwright.
  • Hiểu một test chạy từ đầu đến cuối như thế nào.

  • Gherkin và Cucumber ở mức đọc, viết và mapping được một flow.
  • Mini project gồm ít nhất 5 test case độc lập.

1.2. Nội dung chỉ đọc để biết

  • XPath axes và CSS selector phức tạp.
  • Locator chaining, `filter`, `nth`, iframe.
  • Upload, download, nhiều tab, drag and drop.
  • Custom fixture, global setup, storage state.
  • API testing, network mocking.
  • Parallel execution, sharding, retry strategy.
  • Report tùy biến và CI/CD.

PHẦN I. KIẾN THỨC NỀN TẢNG CHO NGƯỜI MỚI

3. Trước khi viết test: Hiểu test automation là gì

Một test UI tự động thường có ba phần:

TEXT
Arrange: Chuẩn bị trạng thái ban đầu
Act: Thực hiện hành động
Assert: Kiểm tra kết quả

Ví dụ nghiệp vụ:

TEXT
Arrange: Người dùng mở ứng dụng Todo.
Act: Người dùng nhập "Learn Playwright" và nhấn Enter.
Assert: Todo "Learn Playwright" xuất hiện trên màn hình.

Tương ứng với code:

TS
await page.goto('https://demo.playwright.dev/todomvc/');

await page.getByPlaceholder('What needs to be done?').fill('Learn Playwright');
await page.getByPlaceholder('What needs to be done?').press('Enter');

await expect(page.getByText('Learn Playwright')).toBeVisible();

3.1. Điều gì xảy ra khi chạy test?

Khi chạy lệnh:

BASH
npx playwright test

Playwright thực hiện lần lượt:

TEXT
1. Đọc file playwright.config.ts.
2. Tìm các file test theo cấu hình, thường là *.spec.ts.
3. Khởi động browser theo project được cấu hình.
4. Tạo BrowserContext riêng cho test.
5. Tạo Page, tương đương một tab trình duyệt.
6. Chạy từng dòng trong callback của test.
7. Thu kết quả assertion.
8. Đánh dấu test Passed hoặc Failed.
9. Ghi kết quả vào terminal và report.
10. Đóng tài nguyên sau khi test kết thúc.

3.2. Passed và Failed nghĩa là gì?

  • **Passed:** Tất cả thao tác chạy xong và tất cả assertion đều đúng.
  • **Failed:** Có exception, thao tác hết timeout, locator không xác định đúng element hoặc assertion không đạt.
  • **Skipped:** Test được đánh dấu không chạy.
  • **Flaky:** Test fail ở lần đầu nhưng pass khi retry. Đây là tín hiệu test không ổn định, không nên coi là hoàn toàn tốt.

4.6. Viết testcase đầu tiên

Tạo file tests/first-test.spec.ts:

TS
import { test, expect } from '@playwright/test';

test('user can open Todo application', async ({ page }) => {
  await page.goto('https://demo.playwright.dev/todomvc/');

  await expect(page).toHaveTitle(/TodoMVC/);
  await expect(
    page.getByPlaceholder('What needs to be done?')
  ).toBeVisible();
});

4.7. Giải thích từng ký tự và từng dòng

Dòng 1

TS
import { test, expect } from '@playwright/test';

Giải thích từ trái sang phải:

  • `import`: đưa thành phần được export từ package khác vào file hiện tại để sử dụng.
  • `{ test, expect }`: lấy đúng hai thành phần có tên `test` và `expect`.
  • `test`: hàm dùng để khai báo một testcase.
  • `expect`: hàm dùng để khai báo kết quả mong đợi.
  • `from`: cho biết hai thành phần trên được lấy từ đâu.
  • `'@playwright/test'`: tên package Playwright Test.
  • Dấu nháy đơn bao quanh chuỗi.
  • Dấu `;`: kết thúc statement. TypeScript có thể tự suy ra trong nhiều trường hợp, nhưng khóa học dùng dấu `;` để code nhất quán.

Nếu bỏ dòng import, TypeScript không biết test và expect là gì.

Dòng 3

TS
test('user can open Todo application', async ({ page }) => {

Phân tích cấu trúc tổng thể:

TEXT
test(TEST_NAME, TEST_FUNCTION)

Trong đó:

  • `test(`: bắt đầu gọi hàm `test`.
  • `'user can open Todo application'`: tên testcase, dùng để hiển thị trên terminal và report.
  • Dấu `,`: ngăn cách tham số thứ nhất và tham số thứ hai.
  • `async`: khai báo function có thao tác bất đồng bộ và cho phép sử dụng `await` bên trong.
  • `({ page })`: nhận fixture object rồi lấy thuộc tính `page` bằng destructuring.
  • `page`: một tab browser do Playwright chuẩn bị cho testcase.
  • `=>`: cú pháp arrow function.
  • `{`: bắt đầu phần thân function.

Có thể đọc bằng tiếng Việt:

TEXT
Khai báo một test tên "user can open Todo application".
Khi test chạy, Playwright cung cấp một page.
Thực hiện các câu lệnh nằm trong cặp ngoặc nhọn.

Dòng 4

TS
await page.goto('https://demo.playwright.dev/todomvc/');
  • `await`: chờ Promise hoàn thành trước khi chạy dòng tiếp theo.
  • `page`: tab browser hiện tại.
  • Dấu `.`: truy cập method hoặc property của object.
  • `goto(...)`: yêu cầu page điều hướng đến URL.
  • URL trong dấu nháy đơn là trang cần mở.

Luồng thực tế:

TEXT
Code gửi yêu cầu điều hướng
→ Browser mở URL
→ Playwright chờ điều kiện tải trang của goto
→ Promise hoàn thành
→ Test chuyển sang dòng assertion đầu tiên

Nếu bỏ await, code có thể chuyển sang assertion khi thao tác điều hướng chưa hoàn thành.

Dòng 6

TS
await expect(page).toHaveTitle(/TodoMVC/);
  • `expect(page)`: đối tượng cần kiểm tra là trang hiện tại.
  • `.toHaveTitle(...)`: mong title của trang thỏa điều kiện.
  • `/TodoMVC/`: regular expression, nghĩa là title cần chứa chuỗi `TodoMVC`.
  • `await`: assertion web của Playwright có cơ chế retry nên phải chờ kết quả.

Ví dụ title là:

TEXT
React • TodoMVC

thì /TodoMVC/ vẫn match vì chuỗi có chứa TodoMVC.

Nếu dùng:

TS
await expect(page).toHaveTitle('TodoMVC');

thì Playwright mong title khớp chính xác với TodoMVC, nên có thể fail nếu title đầy đủ là React • TodoMVC.

Dòng 7 đến 9

TS
await expect(
  page.getByPlaceholder('What needs to be done?')
  ).toBeVisible();

Có thể viết trên một dòng:

TS
await expect(page.getByPlaceholder('What needs to be done?')).toBeVisible();

Tách thành nhiều dòng chỉ để dễ đọc.

  • `page.getByPlaceholder(...)`: tìm element có thuộc tính placeholder tương ứng.
  • Placeholder là chữ gợi ý nằm trong input khi chưa nhập dữ liệu.
  • Kết quả của `getByPlaceholder` là một `Locator`, không phải text và cũng chưa phải thao tác click.
  • `expect(locator)`: chọn locator đó làm đối tượng cần kiểm tra.
  • `toBeVisible()`: mong element đang hiện và người dùng có thể nhìn thấy.

Luồng retry:

TEXT
Playwright tìm input
→ Nếu chưa visible, chờ và tìm lại
→ Nếu visible trước timeout, assertion pass
→ Nếu vẫn không visible khi hết timeout, assertion fail

Dòng cuối

TS
});
  • `}`: đóng thân arrow function.
  • `)`: đóng lời gọi hàm `test`.
  • `;`: kết thúc statement.

4.8. Test chạy cụ thể từ đầu đến cuối

Khi chạy:

BASH
npx playwright test tests/first-test.spec.ts --headed

thứ tự xảy ra là:

TEXT
1. CLI đọc playwright.config.ts.
2. CLI tìm file tests/first-test.spec.ts.
3. TypeScript được xử lý để có thể thực thi.
4. Dòng import nạp test và expect.
5. Hàm test đăng ký testcase với Playwright runner.
6. Runner khởi tạo browser context độc lập.
7. Runner tạo page.
8. page.goto mở TodoMVC.

Ngày 2: TypeScript tối thiểu để đọc automation test

5.1. Mục tiêu

Học viên đọc được biến, kiểu dữ liệu, array, object, function, class, import/export và async/await ở mức sử dụng trong test.

5.2. Biến và kiểu dữ liệu

TS
const applicationName: string = 'TodoMVC';
let todoCount: number = 0;
const shouldComplete: boolean = true;

Dòng 1

TS
const applicationName: string = 'TodoMVC';
  • `const`: khai báo biến không được gán lại.
  • `applicationName`: tên biến.
  • `:`: bắt đầu khai báo kiểu.
  • `string`: giá trị phải là chuỗi.
  • `=`: gán giá trị.
  • `'TodoMVC'`: giá trị chuỗi.

Không hợp lệ:

TS
applicationName = 'Other App';

vì biến được khai báo bằng const.

Dòng 2

TS
let todoCount: number = 0;
  • `let`: biến có thể được gán lại.
  • `number`: kiểu số.

Hợp lệ:

TS
todoCount = todoCount + 1;

Dòng 3

TS
const shouldComplete: boolean = true;
  • `boolean`: chỉ nhận `true` hoặc `false`.

5.3. Array

TS
const todoNames: string[] = [
  'Learn TypeScript',
  'Learn Playwright'
];
  • `string[]`: array mà mỗi phần tử phải là string.
  • `[` và `]`: bắt đầu và kết thúc array.
  • Dấu phẩy ngăn cách các phần tử.

Duyệt array:

TS
for (const todoName of todoNames) {
  console.log(todoName);
}
  • `for...of`: lấy lần lượt từng giá trị.
  • Lần lặp đầu, `todoName` là `Learn TypeScript`.
  • Lần lặp sau, `todoName` là `Learn Playwright`.

5.4. Object

TS
const todoData = {
  title: 'Learn Playwright',
  completed: false
};

Object có hai property:

TEXT
title     → Learn Playwright
completed → false

Đọc property:

TS
console.log(todoData.title);
console.log(todoData.completed);

5.5. Function

TS
function createTodoTitle(index: number): string {
  return `Todo item ${index}`;
}
  • `function`: khai báo function.
  • `createTodoTitle`: tên function.
  • `index: number`: function nhận một tham số số.
  • `: string`: function phải trả về chuỗi.
  • `return`: trả kết quả cho nơi gọi.
  • Backtick cho phép chèn biến bằng `${...}`.

Gọi function:

TS
const title = createTodoTitle(1);

Kết quả của title là:

TEXT
Todo item 1

5.6. Async function và Promise

TS
async function getStatus(): Promise<string> {
  return 'Created';
}

async function run(): Promise<void> {
  const status = await getStatus();
  console.log(status);
}
  • Function có `async` luôn trả về Promise.
  • `Promise<string>` nghĩa là sau khi hoàn thành sẽ cho một string.
  • `Promise<void>` nghĩa là function bất đồng bộ nhưng không trả dữ liệu nghiệp vụ.
  • `await getStatus()` chờ Promise hoàn thành rồi gán kết quả vào `status`.

Liên hệ Playwright:

TS
await page.goto(url);
await input.fill(value);
await button.click();

Browser cần thời gian xử lý nên các method trên trả Promise.

Ngày 4/14

Ngày 4: Locator cơ bản và cách suy luận

7.1. Locator là gì?

Locator là mô tả giúp Playwright tìm element tại thời điểm thực hiện action hoặc assertion.

TS
const saveButton = page.getByRole('button', { name: 'Save' });

Dòng này chưa click. Khi chạy:

TS
await saveButton.click();

Playwright mới dùng mô tả locator để tìm button phù hợp rồi thực hiện click.

7.2. Thứ tự ưu tiên

TEXT
1. getByRole: element có vai trò và accessible name rõ.
2. getByLabel: input được gắn với label.
3. getByPlaceholder: input có placeholder rõ.
4. getByText: nội dung mà người dùng nhìn thấy.
5. getByTestId: contract dành riêng cho test.
6. locator: CSS hoặc XPath khi thật sự cần.

7.3. Cách chọn locator bằng câu hỏi
TEXT
Element là button, link, checkbox hay heading?
→ Thử getByRole.

Element là input có label?
→ Thử getByLabel.

Input chỉ có placeholder?
→ Thử getByPlaceholder.

Cần kiểm tra một nội dung hiển thị?
→ Thử getByText.

Dev cung cấp data-testid ổn định?
→ Dùng getByTestId.

7.4. Bài thực hành complete Todo

TS
import { test, expect } from '@playwright/test';

test('user can complete a Todo', async ({ page }) => {
  await page.goto('https://demo.playwright.dev/todomvc/');

  const todoInput = page.getByPlaceholder('What needs to be done?');
  await todoInput.fill('Complete locator exercise');
  await todoInput.press('Enter');

  const todoItem = page.getByText('Complete locator exercise');
  await expect(todoItem).toBeVisible();

  const checkbox = page.getByRole('checkbox', { name: 'Toggle Todo' });
  await checkbox.check();

  await expect(checkbox).toBeChecked();
});

> Nếu accessible name thực tế khác, dùng Playwright UI Mode hoặc locator picker để kiểm tra DOM và accessible information. Không đoán rồi tăng timeout.

7.5. Bốn câu hỏi review locator

1. Locator đang dựa vào thông tin nào?

2. Nó có match đúng một element không?

3. Thông tin đó có ổn định không?

4. Nếu test fail, có bằng chứng locator sai hay application chưa render?

8.3. Auto-wait dễ hiểu

Khi gọi click, Playwright thực hiện các actionability checks phù hợp, ví dụ element phải tồn tại, hiển thị và có khả năng nhận tương tác. Khi dùng web assertion, Playwright lặp lại việc kiểm tra cho tới khi pass hoặc hết timeout.

Không mặc định viết:

TS
await page.waitForTimeout(5000);

Vì:

TEXT
UI sẵn sàng sau 200 ms → vẫn phí gần 5 giây.
UI cần 6 giây → test vẫn fail.
Locator sai → chờ bao lâu vẫn sai.

Ngày 8: Page Object Model cơ bản

11.1. Vấn đề

Nếu locator xuất hiện ở mười test, thay đổi UI có thể buộc sửa mười nơi. Page Object gom locator và thao tác UI dùng chung.

11.2. File `pages/TodoPage.ts`

TS
import { expect, type Locator, type Page } from '@playwright/test';

export class TodoPage {
  readonly page: Page;
  readonly todoInput: Locator;
  readonly todoItems: Locator;

  constructor(page: Page) {
    this.page = page;
    this.todoInput = page.getByPlaceholder('What needs to be done?');
    this.todoItems = page.locator('.todo-list li');
  }

  async open(): Promise<void> {
    await this.page.goto('https://demo.playwright.dev/todomvc/');
  }

  async addTodo(title: string): Promise<void> {
    await this.todoInput.fill(title);
    await this.todoInput.press('Enter');
  }

  async verifyTodoVisible(title: string): Promise<void> {
    await expect(this.page.getByText(title)).toBeVisible();
  }

  async verifyTodoCount(expectedCount: number): Promise<void> {
    await expect(this.todoItems).toHaveCount(expectedCount);
  }
}

11.3. Giải thích các phần quan trọng

TS
export class TodoPage
  • `export`: cho phép file khác import class.
  • `class`: khuôn mẫu chứa dữ liệu và hành vi liên quan đến Todo page.
TS
constructor(page: Page)

Constructor chạy khi tạo new TodoPage(page). Page từ test fixture được truyền vào Page Object.

TS
readonly todoInput: Locator;

Property chứa Locator và không bị gán lại sau khi khởi tạo.

TS
async addTodo(title: string): Promise<void>

Method nhận test data title, thao tác lên UI và không trả dữ liệu.

11.4. Test sử dụng Page Object

TS
import { test } from '@playwright/test';
import { TodoPage } from '../pages/TodoPage';

test('user can add Todo using Page Object', async ({ page }) => {
  const todoPage = new TodoPage(page);

  await todoPage.open();
  await todoPage.addTodo('Learn Page Object Model');
  await todoPage.verifyTodoVisible('Learn Page Object Model');
  await todoPage.verifyTodoCount(1);
});
